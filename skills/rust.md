# Rust Skill Standards & Idiomatic Guidelines

## 1. Ownership, Borrowing & Lifetimes
* Strictly adhere to Rust's ownership model. Prefer borrowing (`&T` or `&mut T`) over cloning data unnecessarily.
* Avoid using explicitly annotated lifetimes (`'a`) unless the compiler cannot infer life relationships automatically.
* Never use raw pointers or `unsafe` blocks unless interfacing directly with foreign C APIs.
* Enforce interior mutability cleanly using `Mutex<T>`, `RwLock<T>`, or `RefCell<T>` when necessary.

## 2. Error Handling Pattern
* Never call `.unwrap()` or `.expect()` in production application code.
* Handle missing values explicitly using the `Option<T>` enum.
* Handle fail-able tasks using the `Result<T, E>` enum and propagate errors using the `?` operator.
* Use crate libraries like `thiserror` for library error definitions or `anyhow` for top-level application binary error propagation.

## 3. Pattern Matching & Enums
* Leverage Rust's powerful `enum` system to express valid domain states safely.
* Use exhaustive `match` expressions instead of long `if let` chains when handling multi-state logic.
* Use guard clauses (`if`) inside pattern matching blocks to handle complex conditions directly.

## 4. Structs, Traits & Generics
* Derive standard traits (`Debug`, `Clone`, `PartialEq`, `Eq`, `Default`, `Serialize`, `Deserialize`) wherever appropriate.
* Prefer compositional design using Traits over large monolithic struct definitions.
* Implement the `From` and `Into` traits for clean type conversions between custom structures.
* Keep trait bounds concise using the `where` clause syntax for complex function declarations.

## 5. Memory Management & Performance
* Prefer stack allocations over heap allocations (`Box<T>`) for small fixed-size structures.
* Use `String` when owning text data and string slices (`&str`) when reading borrowed text data.
* Use `Vec::with_capacity()` when pre-allocating memory for arrays with known dynamic size.

## 6. Concurrency & Async
* Use `tokio` or `async-std` runtimes for non-blocking asynchronous operations.
* Use message passing concurrency via channels (`tokio::sync::mpsc`) over shared state where possible.
* Ensure shared state across thread boundaries is safely wrapped with `Arc<Mutex<T>>`.

## 7. Code Formatting & Cargo Guidelines
* Follow standard Rust formatting rules strictly generated by `cargo fmt`.
* Ensure zero warnings emitted by `cargo clippy` during compilation.
* Organize module structure logically using `mod.rs` or module files matching module folder names.

## 8. Documentation Standards
* Document all public structs, enums, traits, and functions using triple-slash doc comments (`///`).
* Provide runnable test code examples within function documentation comments.
* Include `# Errors` and `# Panics` sections in documentation for functions returning `Result` or performing validations.

## 9. Security & Safety
* Keep dependencies minimal and audited using `cargo audit`.
* Never bypass memory safety guarantees with raw pointers without explicit structural invariant guards.
* Protect against integer overflow using checked arithmetic (`checked_add`, `saturating_mul`).

## 10. Testing Practices
* Place unit tests in a inline sub-module annotated with `#[cfg(test)]`.
* Place integration tests inside the dedicated `tests/` directory at crate root.
* Use property-based testing tools like `proptest` for validating complex logic inputs.
